# TravelMap 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** TravelMap 2.0 mit Hub-Navigation in Navy, Indigo und Gold, änderbarem Profilbild und Stories an Pins (Datum, Fotos, Text, Sprachnotiz, Spotify-Song).

**Architecture:** Die Sidebar wird durch eine Tab-Leiste mit vier Sheets ersetzt, die bestehenden Listen ziehen unverändert in die Sheets um. Stories liegen in `users/{uid}/stories`, ihre Medien in Firebase Storage ohne Download-Links, geschützt durch Storage-Regeln, die Firestore abfragen. Die Song-Suche läuft über eine Callable Function. Reine Logik steht in `*-logic.js` und wird mit Vitest getestet, UI-Dateien bleiben dünn.

**Tech Stack:** Vanilla JS (ES-Module, kein Bundler), Capacitor 8 (WKWebView), MapLibre, Firebase 10.12.0 (Auth, Firestore, neu Storage und Functions), Vitest, Firebase Emulator.

**Spec:** `docs/superpowers/specs/2026-11-14-update-2-0-design.md`. Mockups: `docs/design/mockups/accent-c-gold.png` und `screen-*.png`.

## Global Constraints

- Ponytail-Regeln und "iOS zuerst" aus `CLAUDE.md` gelten für jede Aufgabe. Keine neuen npm-Abhängigkeiten im Frontend außer den Firebase-SDK-Dateien.
- Jede geänderte JS- oder CSS-Datei: `?v=` in allen Importen und in `map.html`/`index.html` erhöhen. Neue Dateien starten mit `?v=1`.
- Alle sichtbaren Texte über `js/i18n.js`, Deutsch (du) und Englisch. Keine Gedankenstriche in sichtbarem Text.
- Farben: Fläche Navy `#080b11`, Sekundär Indigo `#6366f1`, Akzent Gold `#facc15`, im hellen Theme `#ca8a04` für Linien und Text. Gold nie für Fließtext, auf Gold steht dunkler Text `#080b11`.
- Grenzen: 10 Fotos pro Story, Foto höchstens 1600 px und 1 MB JPEG, Sprachnotiz höchstens 120 s und 3 MB `audio/mp4`, Text höchstens 2000 Zeichen, Profilbild 512 px quadratisch.
- Stories nur an besuchten und gelebten Städten des eigenen Kontos. Schlüssel ist der Stadtname (`city.name`).
- Für Story-Medien wird nie `getDownloadURL` aufgerufen.
- Branch `feature/v2`. Commit-Nachrichten kurz im Imperativ, englisch, wie im Repo üblich.
- Nach jeder Aufgabe: `npm test` grün. Aufgaben mit Regeln zusätzlich `npm run test:rules`.
- UI-Aufgaben werden im iOS-Simulator geprüft (`npm run ios:sync`, dann Build), mit Screenshot gegen das Mockup.

## Review Focus

1. Upload bricht mitten in einer Story ab (Funkloch): keine halbe Story, bereits hochgeladene Dateien werden gelöscht, die Eingaben im Formular bleiben. Test in Aufgabe 6.
2. Mikrofonzugriff abgelehnt: das Formular bleibt benutzbar, es erscheint ein Hinweis, Speichern ohne Sprachnotiz geht. Test in Aufgabe 8.
3. Eine Stadt mit Stories wird entfernt oder beim erneuten Hinzufügen ersetzt: Stories werden nach Rückfrage mit gelöscht, verwaiste Stories erzeugen keinen Ring. Test in Aufgabe 5 und 7.
4. Ein Freund hat den Viewer offen, während die Story privat gestellt wird: der Viewer zeigt einen Hinweis statt eines kaputten Bildes und schließt. Test in Aufgabe 7.
5. Sehr großes oder ungewöhnliches Foto (Panorama, HEIC, 48 MP) oder eine Datei, die kein Bild ist: Verkleinern klappt oder die Datei wird mit Hinweis abgelehnt, der Rest der Auswahl bleibt. Test in Aufgabe 3.
